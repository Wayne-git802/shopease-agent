## 4. QueryGrounder — 查询落地层

**问题**：
- "推荐礼物"直接查数据库，只匹配商品名含"礼物"
- "有什么好看的"无品类锚点，搜索结果为空

**设计**：
- 新增 `agents/graph/grounding.py`
- `ProductLexicon`: 三类标签（category / abstract_goal / descriptor）
- `ground(query)`: 纯词法提取 slots（category, abstract_goal, descriptor, budget, recipient, occasion, usage）
- `plan(slots, depth)`: 三态决策 `READY` | `NEEDS_REFINEMENT` | `NEEDS_CATEGORY`
- `GroundingMemory`: 约束积累（非 query string merge）
- `build_clarify_reply()`: 确定性模板回复
- `MAX_CLARIFY_DEPTH = 2`: 防止无限 clarify loop

**路由规则**：
| 查询 | 状态 | 行为 |
|------|------|------|
| "推荐耳机" | READY | 直接搜索 |
| "推荐礼物" | NEEDS_CATEGORY | clarify category |
| "送给女朋友的礼物" | NEEDS_REFINEMENT | 搜索（有辅助约束） |
| "有什么好看的" | NEEDS_CATEGORY | clarify category |
| "第一个看看" | 跳过（有 card + 无新锚点） | DisplayContext |

**时序**：00:20–01:25

**文件**：
- `backend/agents/graph/grounding.py`（新建，~220 行）
- `backend/agents/graph/orchestrator.py`（+35 行插入）

## 6. Grounder 跳过逻辑迭代

**问题 v1**（词表方案）：
- `_CONTEXT_REF_PATTERNS` 硬编码"第一/那个/看看"，"耳机"（2字）被误判为 context ref

**问题 v2**（`_has_strong_intent` 方案）：
- "第一个看看"中"看看"在 commerce 关键词里 → `_has_strong_intent=True` → 跳过失败

**最终方案 v3**：
- `ground(query)` 提取品类锚点 → `has_new_anchor = bool(category)`
- `has_cards AND NOT has_new_anchor` → 跳过 grounder
- 不依赖任何词表或 `_has_strong_intent`

**文件**：
- `backend/agents/graph/grounding.py`（删 `_CONTEXT_REF_PATTERNS` + `is_context_reference`）
- `backend/agents/graph/orchestrator.py`（改 skip 逻辑）

## 剩余问题

### P1: 直接输入商品名，Agent 不展示 card
- **现象**：用户输入完整商品名（如 "Soundmagic PL30"）→ LLM chat 回复，无 product_card + 操作选项
- **预期**：识别为已知商品 → 展示 product_card + 询问"加入购物车 / 立即购买 / 查看详情"
- **可能根因**：commerce_intent 把完整商品名当 chat / 无 signal match → 不进 graph search

### P2: 数量 + 序号指代理解失败
- **现象**："买3个第二个" → "无法确定你指的是哪个订单"
- **预期**：解析 `quantity=3, index=2` → 找到 display context 中第 2 个商品 → 加购物车或下单
- **可能根因**：DisplayContext / CartAgent 未处理复合指代（序号 + 数量）

## 架构演进总结

```
本次新增的层：
  WorkflowAffinityRouter  (P0: block-driven)
  QueryGrounder            (L1.5: executability gate)
  GroundingMemory          (constraint accumulation)

当前完整路由链路：
  query
    ↓
  WorkflowAffinityRouter   — 最近 assistant block → 亲和路由
    ↓
  Dialogue context merge   — follows-up merge
    ↓
  L0 state_router          — 大类意图
    ↓
  L1 commerce_intent       — commerce 子意图
    ↓
  L1.5 QueryGrounder       — 可执行性门控（READY / clarify / skip）
    ↓
  L2 FinalDecision         — 单一真理源
    ↓
  Agent dispatch           — order / purchase / cart / commerce
```
